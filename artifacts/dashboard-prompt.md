## 貼這一段

請幫我做一個 **【技能庫】儀表板**，發佈成 Claude Artifact。

### 一、資料來源與內容

- 掃描來源：**【`/mnt/skills/examples`（範例）、`/mnt/skills/public`（內建）、
  `~/.claude/skills/synced`（自建，並讀 `manifest.json` 取得啟用狀態）】**
- 每個項目要取得：**【名稱、說明（frontmatter description）、來源、是否啟用、
  檔案數、大小、最後更新日、路徑】**
- 人工維護欄位（掃描拿不到，要由我補）：**【中文名、分類、一句話用途】**
- 分類：**【文件處理、設計視覺、生活助理、購物電商、投資理財、行政庶務、
  系統維運、情報研究、開發工具、內容創作】**

### 二、先講清楚這個限制，架構要照它來

已發佈的 Artifact 跑在沙箱 iframe 裡：**沒有檔案系統權限**，CSP 只放行
Google Fonts。**頁面永遠無法自己去掃描目錄**，所以掃描與呈現一定要拆開：

1. **掃描器**（Python，在讀得到檔案的環境執行）→ 輸出 JSON 清單，含 `scannedAt`。
2. **頁面**：每次開啟都 `fetch` 自己的資料檔（例如 `data/items.json`），
   讀不到或格式壞掉就退回頁面內嵌的快照——**壞掉的資料檔絕不能讓整頁空白**。
3. **寫回資料檔**：頁面內做一個「更新清單」面板，貼上掃描輸出後驗證、
   顯示新增／移除／異動的筆數與名稱，再用 artifact capability 的檔案式發佈
   （`publish({"data/items.json": json})`）寫入。**這是頁面唯一能寫入資料檔的管道**，
   因為 Artifact 工具只能發佈 HTML。

### 三、以下七個坑請直接避開

1. **`window.storage` 這個 API 不存在。** 要保存狀態就用 artifact capability
   （`await claude.use("artifact")`），並以 `localStorage` 當退路。錯用會被
   try/catch 吞掉，看起來正常但什麼都沒存到。

2. **絕對不要用 `data-theme` 當自己的主題屬性。** 檢視器會依讀者的 claude.ai
   佈景，在 `<html>` 上蓋 `data-theme="light|dark"` 加 inline `style.colorScheme`。
   配色若掛在這個屬性上，讀者的個人設定會蓋掉頁面預設。請改用自己的屬性名
   （例如 `data-skin`），與外層完全脫鉤。

3. **不要把「從 DOM 讀到的主題值」存成使用者偏好。** 那讀到的是檢視器蓋的值。
   主題只能由切換鈕的 click handler 寫入，並且**存在獨立的 key**，不要跟
   檢視／排序偏好放在同一包——否則按一下排序就會把外層的佈景寫成「使用者的選擇」。

4. **`color-scheme` 要宣告在 `body`**，才贏得過從 `<html>` inline 繼承下來的值，
   日期選擇器與捲軸才會跟著本頁配色。

5. **統計數字一律從資料算**，不要寫死在標題或副標裡，很快就會過期。
   時間戳要誠實：「開啟頁面的時間」和「掃描資料的時間」是兩件事，分開標示。

6. **重新掃描不可以覆蓋人工欄位。** 掃描器要依名稱從舊清單沿用中文名、分類、
   用途；新掃到的項目標記成「待補」並在卡片上顯示，不要默默塞一個預設分類。

7. **資料檔與內嵌快照都要帶 `scannedAt`，開頁時取較新的那份。**
   否則兩條更新路徑（手動匯入 vs 排程重發）會互相蓋掉。

### 四、頁面要有的功能

搜尋（名稱／用途／說明全文，命中處高亮）、依分類與來源篩選、只看已啟用、
多種排序、卡片與清單兩種檢視、詳細面板（說明全文、檔案樹、實際路徑）、
拖曳調整順序並保存、標示清單來源與掃描時間。

### 五、設計

- 深色為預設。配色、字體請自己做選擇，**不要用 AI 常見的那幾套**
  （奶油色配襯線、近黑配單一螢光色、Inter／Space Grotesk、emoji 當小標）。
- 分類色請校準成同一組明度與彩度，不要隨機取色；相鄰分類不要用同一個色相。
- 卡片不要用「左側色條配圓角卡」這種樣板感的組合——除非我另外指定。

### 六、驗收（請實際跑，不要只說「應該可以」）

用瀏覽器自動化（Playwright）寫斷言並執行，至少涵蓋：

- 搜尋、每一種篩選與排序、兩種檢視、手機寬度無橫向捲動；
- 主題：**模擬檢視器蓋上 `data-theme="light"` 與 inline `color-scheme:light`**
  的情況，確認頁面仍照自己的預設呈現，切換鈕雙向都能保存；
- 資料檔：不存在／格式壞掉／比快照舊／比快照新，四種情況各自的行為；
- 匯入：壞 JSON 只報錯不動清單、好 JSON 正確顯示新增與移除。

跑完把通過與失敗逐條列出來給我看。

## 選配：每天自動更新

如果要讓它自己跟上，再加這一段。**先說清楚代價**：延遲等於排程間隔，
「剛剛新增的東西」不會立刻出現，這是沙箱限制拿不掉的。

請建立一個排程（**【台北時間每天 09:00】**），每次執行：

1. 切到**存放腳本的分支**再找檔案。（repo 的預設分支可能沒有這些腳本。）
   **明確禁止用 `find` 掃描磁碟找檔案**——排程執行時沒有人能批准權限請求，
   一問就永遠卡住。
2. 用 Artifact 的 `read` 取得**目前線上那一版**當比對基準。
3. 重新掃描，與基準逐欄位比對（忽略時間戳）。
4. **相同就直接結束，不發佈**，避免每天灌一個版本。
5. 有差異才改寫內嵌快照並重新發佈（**發佈時要帶 `url`**，否則會另建一個新頁面）。

排程流程裡**不要放 git commit / push**：排程 session 不見得有推送權限，
而且比對基準若用 repo 裡的檔案，推不上去時基準永遠不會前進，同一個變動會
每天被重新發佈一次。線上頁面才是排程唯一能可靠寫入的狀態。

**建立完請實際觸發一次驗證**，不要只建好就說完成。至少要驗兩種情況：
有差異時會發佈到正確的網址（不是新建一個），沒差異時什麼都不做。
